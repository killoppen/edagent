# 从旧岗位包到黄金岗位包 1.0.0 的语义 Diff

对比基线：`../role-snapshot/packages/llm-app-engineer-v1.1` 与伴随事理包 `llm-app-engineer-process-v0.1`

新版本：`role-package:llm-app-engineer-golden@1.0.0`

快照：`snapshot:role:llm-app-engineer@2026-08-24-gold-v1`

## 保留

- 岗位稳定 ID `role:llm-app-engineer` 与“大模型应用工程师”名称。
- RAG、Agent、Prompt/上下文、评测、发布、可观测与迭代作为重要工作内容。
- 人工智能工程技术人员和生成式人工智能系统应用员两个正式职业节点。
- evidence / semantic / process 三空间与 Composite Snapshot 读取协议。

## 岗位锚点修订

- 人工智能工程技术人员由旧包的“相邻”提升为工程主锚，依据国家标准中的人工智能应用产品集成实现方向。
- 生成式人工智能系统应用员由旧包的“主锚”调整为专项规范映射；不是删除，而是避免用更宽的应用操作职业替代工程技术岗位。
- 显式记录 2021 旧编码 `2-02-10-09` 到 2022 现行编码 `2-02-38-01` 的版本沿革。

## 能力结构重建

旧包 6 项能力中存在任务、思维方式和具体技术混合。新包重建为 5 项跨任务能力：

1. 业务场景分析与 AI 方案判断；
2. 大模型应用架构与集成工程；
3. 证据与度量驱动的质量工程；
4. 生产可靠性、安全与治理；
5. 协作交付与生命周期改进。

每项能力再拆成有工作产物和测评证据的能力单元，避免“度量先行思维”等不可直接观察节点。

## 知识技能修订

- 从混合的 `knowledge_skill` 标签中显式区分 17 个 knowledge 与 18 个 skill。
- 为每个节点增加适用位置和可观察结果。
- 新增前置关系，形成可用于学习路径的依赖结构。
- “性能分析”“RAG优化”“持续跟踪前沿”等空泛表述进入冻结语义负例。
- PEFT/LoRA 保留，但节点和关系均标为 candidate / conditional。

## 事理森林替换

旧事理包 3 棵树中“技术雷达”占一棵，RAG 新建流程缺失，参与者节点在图上孤立，关系多为无片段的推断。新包替换为：

- 从业务需求到应用发布；
- 更新知识并守住 RAG 检索质量；
- 执行高影响 Agent 工具调用；
- 诊断线上坏例并恢复生产质量。

四棵树覆盖 44 个事件、57 条顺序/分支/返工主流程，以及参与者、对象、产物、工具、质量门槛和异常风险关系。

## 证据层变化

- 来源：35 个旧来源台账对象变为 29 个重新资格审查的来源；数量减少不表示证据变弱。
- 片段：从极少量片段级绑定提升为 99 个可定位片段。
- Claim：55 条，其中 47 accepted、3 disputed、5 rejected。
- 稳定节点与关系均有片段级绑定；搜索摘要不直接进入事实层。
- 公开 Issue 只以 limited 资格支撑版本与环境特定的工作事件。

## 兼容变化

只增加可选字段：来源类型与局限、片段定位与摘录类型、断言类型与证据强度、知识/技能标识、过程引用、验收标准、工具/质量/异常节点和桥接证据。旧 v2/v3 数据仍可读取。

为读取新增过程类型，仅补齐 `lib/projects/presentation.ts` 的投影映射；为桥接关系下钻证据，仅让 `lib/agent/snapshot-runtime.ts` 读取可选绑定。未修改冷启动、迭代、Hub、前端交互或 Agent 编排。

# 大模型应用工程师岗位边界审查

审查时点：2026-08-24

岗位稳定 ID：`role:llm-app-engineer`

结论状态：已由用户确认

## 结论

保留“大模型应用工程师”作为企业岗位实例名，不改名、不拆岗、不更换现有岗位 ID。

- 工程主锚：人工智能工程技术人员，现行编码 `2-02-38-01`。
- 专项规范映射：生成式人工智能系统应用员，编码 `4-04-05-13`。
- 教育映射：人工智能技术应用专业 `510209` 中的人工智能应用开发、系统集成与运维方向。

这里的三层关系不是同义词：企业岗位实例用于解释市场工作，工程主锚提供正式工程职业范围，专项规范映射补充生成式人工智能的设计、调用、优化、部署和支持活动。

## 证据判断

1. 2022 年职业分类大典把人工智能工程技术人员列为 `2-02-38-01`，职业范围同时包含算法活动和人工智能系统的设计、集成、部署、运维与应用。
2. 2021 年国家职业技术技能标准虽使用发布时旧编码 `2-02-10-09`，但设置了正式的“人工智能应用产品集成实现”方向，覆盖需求、设计开发、交付、运维与咨询。因此两个编码是版本沿革，不是两个并列职业。
3. 2024 年新职业信息将生成式人工智能系统应用员定义为设计、调用、训练、优化、部署、更新和支持生成式 AI 系统的人员，但该文件不是完整分级职业技能标准，范围也宽于企业工程岗位。
4. 2025 年人工智能技术应用专业教学标准把专业面向连接到人工智能工程技术人员，并明确人工智能应用开发、系统集成与运维。
5. 字节、滴滴、中船、荔枝、帆软、复旦等企业样本共同支持业务需求、RAG/Agent/Prompt、系统集成、评价、部署和迭代；但微调、私有化推理、前端、平台内核的出现具有企业与层级条件。

## 与相邻岗位的可执行边界

| 相邻岗位 | 交叉区 | 划界测试 |
|---|---|---|
| 大模型算法工程师 | 模型选择、实验、条件性 PEFT | 主要交付若是模型算法、预训练/后训练或深度模型优化，归算法岗；有限适配不改变岗位身份 |
| AI Agent 工程师 | 工作流、工具调用、状态、人工介入 | 业务 Agent 的实现和交付属于本岗位方向；通用 Agent 平台内核属于 AI Infra 边界 |
| 后端工程师 | API、数据库、异步服务、测试发布 | 只做通用业务服务且不承担模型行为、知识链路或 AI 质量闭环，归后端岗 |
| MLOps/LLMOps / AI Infra | 部署、监控、性能成本 | 应用侧发布、观测和回滚属于本岗位；组织级算力、模型网关、训练推理和通用平台归平台岗 |

## 稳定内核与条件职责

稳定内核：场景与验收、方案判断、RAG、Agent/工具集成、上下文与行为控制、质量安全评测、应用服务发布、生产诊断与迭代。

条件职责：PEFT/LoRA、自托管推理与量化、前端全栈、组织级平台、复杂多智能体。条件职责保留为候选或相邻边界，不因少数 JD 出现就上升为所有层级的核心任务。

## 未选择的边界方案

- 改名为“生成式人工智能系统应用员”：未选择。会把企业工程岗位与更宽的应用操作职业混为一体，并造成名称和 ID 迁移。
- 立即拆为“应用交付岗”和“Agent/平台岗”：暂缓。现有证据更支持业务 Agent 是本岗位方向、通用平台是相邻岗位；若未来多数样本形成两组互斥稳定任务，再重新审查。

## 重新打开边界确认的触发条件

- 跨行业样本显示模型后训练而不是应用交付成为多数岗位的稳定价值中心；
- 正式职业标准发布直接定义“大模型应用工程师”且与本包不兼容；
- 冻结评测发现一个岗位身份无法解释应用交付与平台底座两组互斥任务。

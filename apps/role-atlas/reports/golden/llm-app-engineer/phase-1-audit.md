# 阶段 1：现有资产审计

审计时点：2026-08-24

## 对黄金岗位包目标的理解

黄金岗位包不是冷启动演示数据，也不是一次大 Prompt 的输出。它是使用现有 Role Package v3 协议表达的静态、不可变、可追溯岗位知识产品，同时承担人工内容基准、结构与证据回归基准、Agent 回答基准，以及“典型工作任务转学习任务”的稳定接口。

## 当前资产位置

- 产品协议、构建器与读取工具：`role-agent/lib/build`、`role-agent/lib/packages`、`role-agent/lib/agent`。
- v3 Composite Snapshot 协议文档：`README.md` 与 `docs/`。
- 旧内置语义岗位包：`../role-snapshot/packages/llm-app-engineer-v1.1`。
- 旧候选包装版本：`../role-snapshot/packages/llm-app-engineer-v1.2`。
- 旧伴随事理包：`../role-snapshot/packages/llm-app-engineer-process-v0.1`。
- 旧包在 `role-agent` 中通过适配器读取，没有原生 v3 黄金发布目录。

旧语义包包含 54 个节点、105 条边、35 个来源、22 条 assertion、6 个 insight 和 6 个 gap；旧事理包包含 3 个推断场景，没有企业内部 observed episode。

## 最严重质量问题

1. 证据层：旧适配器统计显示高覆盖，但实际直接片段绑定约为 2.59%；大量节点和关系只有来源级背景或模型综合，无法定位原文。
2. 断言层：直接事实、跨来源归纳和研究推断没有稳定分开，数值 confidence 形成无法解释的精确感。
3. 任务层：10 项任务同时包含核心工作、条件性技术、持续活动和生命周期支持，微调、推理优化、技术雷达、培训被抬成普遍核心。
4. 能力层：岗位能力、思维方式、能力单元和工具技术混合；部分能力不能跨任务，部分能力单元不可观察。
5. 知识技能层：知识与技能混标，缺少前置关系、应用位置和验收结果；“性能分析”等节点无法直接课程化。
6. 事理层：3 棵树全部为推断；技术雷达占用一棵代表树，RAG 新建流程缺失；参与者与事件关系不足，语义图和事理图部分重复。
7. 读取层：旧伴随包的桥接方向假设使从 `task:T-03` 追踪过程时返回空结果；现有测试没有覆盖这一情况。
8. 时间与范围：2021 职业标准旧编码、2022 现行编码、2024 新职业之间的版本和映射关系不够清楚；企业样本偏正式组织。

## 建议保留、迁移和废弃

- 保留岗位 ID、三空间协议、静态包发布与读取工具。
- 迁移旧任务到描述性稳定 ID，并通过 `reference-migrations.json` 显式记录拆分、改名、降级和并入。
- 废弃把旧数值 confidence 当作事实概率的解释；为了协议兼容只保留三档固定投影。
- 废弃“来源数量多即可靠”、搜索命中直接入图、工具名当能力、持续状态当任务的做法。
- 不删除有价值的争议内容；转成 disputed、rejected 或 conditional。

## 初步岗位边界假设

保留“大模型应用工程师”及当前 ID；以人工智能工程技术人员作为工程主锚，以生成式人工智能系统应用员作为专项规范映射。业务 Agent 属于岗位方向，通用 Agent 平台属于 AI Infra；后端能力是实现基础，算法后训练和组织级 LLMOps 是相邻或条件职责。

该假设随后经正式标准、企业岗位和技术工作事件研究支持，并由用户确认，详见 `boundary-review.md`。

## 来源研究计划

1. 正式职业分类、职业技术技能标准、专业教学标准和监管文件；
2. 跨行业企业正式岗位页面，并区分目标岗位和相邻岗位；
3. 官方技术文档与行业安全资料，用于方法和验收，不用于证明市场普遍性；
4. 真实仓库 Issue，用于复现、异常、返工和回滚证据；
5. 每个来源先资格审查，再抽片段、建 Claim，最后进入任务骨架。

## 兼容方案

不另建信息架构。仅给现有 v3 类型增加可选字段：来源类别与局限、片段定位与摘录类型、断言类别/证据强度/范围限制、知识与技能标识、过程任务/参与者/产物引用、验收标准、工具/质量/异常节点和桥接证据。旧包缺少这些字段时继续按原逻辑读取。

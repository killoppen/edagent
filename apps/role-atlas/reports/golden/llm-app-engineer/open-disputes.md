# 争议与待研究问题

版本：1.0.0

原则：争议不删除、不伪装为事实，也不阻塞稳定内核发布。

## D01：PEFT/LoRA 是否为所有岗位的核心任务

状态：disputed / weak。

支持面：生成式人工智能系统应用员职业活动包含训练与优化；中船等部分岗位要求模型微调；PEFT 官方资料提供明确技术路径。

限制面：滴滴、荔枝、复旦等样本把微调放在优先项、可选经验或算法协作范围；应用交付可以通过模型选择、RAG、Prompt和工作流完成。

本版处理：不单列核心任务；保留条件性知识与技能。需要更多跨行业样本和真实项目事件才能提升。

## D02：自托管推理和量化是否为普遍核心

状态：disputed / weak。

支持面：私有化、高并发或量化企业岗位会要求推理部署、性能与成本优化。

限制面：使用托管 API 的企业不需要维护推理集群；组织级通用推理平台通常由 LLMOps/AI Infra 负责。

本版处理：应用侧性能、容量、发布和回滚保留；集群、框架和组织级平台不进入稳定任务内核。

## D08：MCP 无浏览器机器授权是否已有统一方案

状态：disputed / weak。

当前证据是已关闭公开 Issue 中的现场问题和本地 HMAC 方案，不是生效的 MCP 规范。后续应跟踪正式授权规范和安全指南，不得把 Issue 提案回答为标准方案。

## 企业代表性

当前企业样本覆盖互联网、软件、央企、科研教育和量化，但大型和正式组织仍占较多。小型企业可能把前端、后端、适配和运维组合到同一岗位；本版只把这种现象记为条件差异，不上升为稳定内核。

## 真实工作事件

当前没有企业内部完整工作事件包。公开 Issue 提供了复现与诊断片段，但不能证明完整岗位流程频率。因此三棵事理树标为 documented_norm，一棵标为 inferred_pattern。获得脱敏工作材料后，应按事件逐条升级而不是整体改成 observed。

## 法规适用

生成式人工智能服务管理暂行办法不能被回答成对所有企业内部应用全部适用。具体项目仍需按是否面向境内公众提供服务、数据和个人信息处理、行业规则与组织政策逐项判断。本岗位包不提供法律结论。

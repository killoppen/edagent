# 第一轮实现决策

## 请求路径

```text
用户问题 + 精确节点引用
        ↓
固定 package/version/snapshot
        ↓
确定性计划器（最多 6 个调用）
        ↓
8 个只读岗位工具（并行、去重、有界）
        ↓
覆盖检查 + 引用注册表
        ↓
MiMo / DeepSeek OpenAI-compatible 适配器
        ↓
reasoning_content / content 双通道原样流
        ↓
NDJSON 事件流 → 进程卡 / 思考过程 / 答案 / 引用卡
```

## 为什么暂不让模型直接调用工具

第一轮首先验证信息架构能否被稳定、快速地使用。确定性路由让工具选择可复现、调用数有界，也便于建立评测基线。后续可以增加“模型提出计划—策略层校验—工具执行”的二级规划；引用版本、参数上限与结果信封继续约束工具层，但不对模型正文设置后置门禁。

## 故障语义

- 对象不存在：批量读取部分成功；单点图查询返回 `OBJECT_NOT_FOUND`。
- 快照不一致：返回 `SNAPSHOT_MISMATCH`，禁止自动映射到新版本。
- 重复调用：复用本轮缓存并标记 `DUPLICATE_CALL`。
- 零召回：返回成功信封、零结果和 `ZERO_RESULTS`，不伪造补全。
- 供应商鉴权/限流：转成用户可操作的安全消息，不回显上游正文或密钥。
- 模型流中断：保留已经收到的思考与正文，并显示可操作的失败状态。
- 取消：AbortSignal 传到图执行与模型请求，岗位包保持只读。

## 下一轮基础设施优先级

1. 用持久化 checkpointer 和运行记录表替代内存检查点，记录事件与工具诊断但永不记录密钥。
2. 建立基于 DeepSeek Harness 测试问题的离线评测集：对象命中率、证据充分率、未知引用率、重点突出度与任务完成率。
3. 为冷启动引入 candidate sandbox、patch proposal、人工裁决与快照发布事务。
4. 把联网深度研究拆成独立来源摄取管线，经过抓取、分段、时间政策和证据绑定后才能进入岗位包。
5. 给多岗位包增加 registry、岗位差异投影和跨包引用协议。

# Role Atlas vNext：证据化岗位包与双层 Agent 架构

## 1. 产品对象

Role Atlas 不是“自动生成一张很大的岗位图”，而是维护一个可追问、可验证、可版本化、可继续研究的 **Role Package（岗位包）**。岗位包是对外唯一的数据对象，内部只有三个命名空间：

1. `evidence`：来源、稳定分段、Claim、证据绑定、时间与置信状态；
2. `semantic`：产业链 / 岗位群 → 岗位 → 典型工作任务 → 岗位能力 → 能力单元 → 知识点 / 技能点；
3. `process`：真实或规范工作场景中的事件、参与者、对象、输入、交付物、条件、分支、返工和结果，并桥接稳定任务 ID。

图谱、卡片、JD、学习路径、对话上下文和报告都只是岗位包的投影，不再分别维护事实。

## 2. 三条认识纪律

### 2.1 证据先于节点

模型先从有资格的来源小分片抽取 Claim、Mention 和工作事件，再经过聚类与规范化形成稳定对象。来源不充分时保留候选、冲突或缺口，不能用“看起来合理”的节点填满界面。

### 2.2 任务是语义图和事理森林的接缝

典型工作任务先形成稳定骨架。知识技能按任务抽取，岗位能力从跨任务行为归纳，工作过程按场景展开。三条 Lane 最终都重写到稳定任务 ID，因此能够检查：

- 某任务缺少哪些可学习知识技能；
- 某能力是否只有抽象措辞、没有跨场景行为证据；
- 某事理场景是否无法映射到岗位任务；
- 某工作区事件是组织实例还是岗位共性。

### 2.3 快照只记录“现在知道什么”

每次成功冷启动、迭代或工作区校准都形成不可变版本。Tag 是人类命名，Release 是分发指针，均不改变快照本体。失败运行只留下日志、检查点和候选产物，不能移动当前岗位包指针。

## 3. 双层 Agent

### 3.1 主 Agent：短路径理解与回答

主 Agent 固定一个具体岗位包版本，只使用六个感知工具：

| 工具 | 责任 |
|---|---|
| `read_role_objects` | 精确读取选中节点或对象 |
| `search_role_knowledge` | 在三个命名空间中检索候选对象 |
| `query_role_graph` | 查询语义邻居与有界路径 |
| `trace_work_process` | 读取场景、事件链、分支、返工及任务桥接 |
| `inspect_role_evidence` | 追溯来源、原文片段、支持强度与时点 |
| `audit_role_package` | 检查结构、重复、覆盖、证据、时效和跨图一致性 |

规划器最多选择四次有明确目的的调用。确定性代码负责引用固定、参数限制、结果去重、版本检查和证据注册；模型负责意图理解、消歧和有据综合。普通问答不会隐式启动联网研究或修改岗位包。

### 3.2 Skills：长任务研究与写入

长任务不塞进主 Agent 的循环。产品只暴露四个渐进式 Skill 元数据，用户启动后才进入完整工作流：

1. 冷启动岗位包；
2. 迭代岗位包（自动发现、目标增强、定向研究统一）；
3. 深化选中节点（复用定向迭代引擎）；
4. 接入真实工作区。

每个 Skill 都运行在追加式 Job Runtime 中。普通事件即时显示并按序持久化；快照、版本等提交边界只有在日志落盘后才对用户可见。`role_jobs` 统一记录任务种类、阶段、尝试次数、检查点和执行租约；心跳续租避免重复执行，租约过期后新执行器可从阶段检查点接管。数据库事件、阶段检查点和不可变版本是恢复依据，单机 `MemorySaver` 不承担生产持久化。

## 4. 冷启动工作流

```text
岗位边界假设
  ↓
检索规划与来源资格判定
  ↓
按来源小分片抽取 Claim / Mention / 工作事件
  ↓
任务聚类与规范化
  ↓
TASK BARRIER：稳定任务骨架 + 快速岗位包
  ↓
┌──────────────────┬──────────────────┬──────────────────┐
│ 按任务抽知识技能 │ 跨任务归纳能力   │ 展开工作事理场景 │
└──────────────────┴──────────────────┴──────────────────┘
  ↓
关系命题重写到稳定 ID
  ↓
结构、证据、重复、时效、跨产物一致性检查
  ↓
只补研缺口，只重跑受影响分片
  ↓
新的不可变岗位包版本
```

快速阶段只生成低信息熵内核：5—9 个任务、3—6 个能力、每个任务少量代表性知识技能和事理胶囊。详细技能依赖、完整事件链和长尾节点在后台增量展开，或在用户深化节点时按需生成。

## 5. 前端投影

- 雷达图默认只展示 `kernel` 对象；详情节点按聚类折叠，不因数据库中节点多就一次铺满。
- 卡片视图按维度纵向分区，同维度横向浏览。
- 事理森林以场景为树根，事件为主干，条件分支与返工为侧枝，并始终显示它桥接的典型任务。
- 对话显示系统可验证的计划、工具、来源、耗时、检查点与提交结果。供应商返回的推理通道可折叠查看，但不作为系统真实状态或质量证明。

## 6. 评测对象

评测单位是“模型 + Harness + 岗位包环境”，不能只评分最终文本。冻结数据应至少覆盖：

- 已知节点的精确、有证据解释；
- 模糊问题的检索、消歧和不越界回答；
- 冷启动在噪声来源下形成稳定任务骨架；
- 工作区实例不被错误提升为岗位共性。

结果指标包括对象正确性、证据可追溯性、跨命名空间一致性、重复率、覆盖率和快照 Diff；过程指标包括无效调用率、输入/输出 Token、首个可用岗位包延迟、总耗时、缓存命中和失败恢复位置。

## 7. 当前实现边界

已经落地：v3 统一岗位包 manifest、旧三包读取兼容、六个主 Agent 工具、四个 Skill 目录、长任务追加日志与提交屏障、跨 Skill 租约和阶段检查点、迭代节点级续跑、后台断连继续执行、不可变版本链。

下一步：将租约任务接入外部队列触发器、冻结评测任务、按节点强化生成、本地目录/ZIP 工作区摄取和 Registry 联邦。

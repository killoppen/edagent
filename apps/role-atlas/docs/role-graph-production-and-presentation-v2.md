# 岗位能力图谱生产与展示 v2

## 1. 产品对象

产品不直接生产一张前端图，而是生产一个可版本化的 Role Package。前端所有视图均是同一岗位包的投影，不复制事实，也不为特定岗位编写专门数据。

岗位包保留三个命名空间：

1. `evidence`：来源、片段、事实主张、推断、时间和争议；
2. `semantic`：产业链 / 岗位群 → 岗位 → 典型工作任务 → 岗位能力 → 能力单元 → 知识点 / 技能点；
3. `process`：场景、事件、参与者、对象、交付物、判断、分支、返工与验收。

典型工作任务是 `semantic` 与 `process` 的稳定接缝。语义图回答“完成什么、需要什么”，事理图回答“工作如何发生”。

## 2. 生产顺序

```text
来源规划与资格判定
  → Claim / Mention / 工作事件抽取
  → 典型工作任务聚类、规范化与稳定 ID
  → TASK BARRIER：形成任务骨架
  → 按任务抽取知识技能
  → 跨任务归纳岗位能力
  → 将能力拆为可观察、可评价的能力单元
  → 按任务展开事理场景与工作事件
  → 将知识技能桥接到具体工作事件
  → 证据、重复、粒度、时效和跨产物一致性检查
  → 编译不可变岗位包版本
```

生产器必须优先形成稳定任务骨架，再并行派生能力、能力单元、知识技能和事理森林。前端不会把无法回写到稳定任务 ID 的模型产物显示为正式任务详情。

## 3. 默认展示层次

### 3.1 总雷达

展示岗位包完整逻辑，回答“这个岗位由哪些结构组成”。核心模式优先显示概括性节点，完整模式显示全部节点。点击典型工作任务进入任务工作台，而不是打开普通浮层。

### 3.2 典型任务工作台

任务可以从总雷达、卡片总览进入，也可以通过 `?task=<stable-id>&taskView=relations|process` 独立寻址。

任务工作台提供两种互补视角：

- **关系雷达**：以任务为中心，展示岗位能力、能力单元和知识技能的稳定关系；
- **事理流程**：展示相关场景的事件、分支、返工、交付物与上下文，并把知识技能附在实际使用它的工作事件上。

完整场景中不直接实现当前任务的事件仍作为“关联上下文”保留，以避免把真实协作流程切碎。

### 3.3 卡片总览

不同语义维度上下排列，同维度节点左右浏览。典型任务卡提供显式“展开任务”入口；其他节点继续支持细节、引用和证据追溯。

### 3.4 来源证据

展示岗位包登记的真实来源和可追溯位置。可以查看全部来源，也可以从任务或节点进入带范围的证据视图；存在 URL 时提供原文链接。

## 4. 跨产物关系

任务详情不得创建新的临时节点 ID。两种视角共享：

- 语义任务 ID；
- 能力、能力单元与知识技能 ID；
- 事理场景和事件 ID；
- 证据来源 ID；
- 岗位包版本与快照 ID。

冷启动、岗位迭代和真实工作区实例化都必须输出相同协议。它们只是不同来源和研究目标，不是三套展示数据。

## 5. 后续生产器验收

每个典型任务至少检查：

- 是否有明确工作对象、动作、交付物和完成边界；
- 是否与其他任务语义重复；
- 是否映射岗位能力和可观察能力单元；
- 是否具有可学习、可实践、可测评的知识技能；
- 是否至少有一个来源或明确标识为待研究；
- 是否有事理场景覆盖，或明确记录 `gap` / `partial`；
- 事理事件上的知识技能是否与语义关系一致。

这些检查用于暴露缺口，不作为删除全部候选内容的质量门。
